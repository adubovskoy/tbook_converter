# B1 — the wrong-language leak becomes a gate, 2026-09-19

Plan item **B1**: make the wrong-language check a gate instead of a report, add the two missing
glossary entry gates, and move the gonka defaults onto the model the served-model probe found
(`PLAN` §3 B1; evidence `E` §3.A A7, §3.B, §3.C, §3.D, §4.1, §4.6, §2.2 N22).

**The headline is a null result on the leak and two real defects found next to it.** Produced at
HEAD with per-target glossaries on `deepseek-ai/DeepSeek-V4-Flash-0731`, two chapters of *The
Adventures of Sherlock Holmes* into ru, de and fr carry **zero** wrong-script sentences in every
language — 100.00 % script-clean taps in all three, in both arms, and the target-script guard never
re-queued a single batch in ~1 300 text requests. The residual leak is **0.14 %** (one German cell,
and it is a false positive), against a kill criterion of 0.5 %. What the run did expose is that
**10 % of this model's replies on this gateway are malformed in a way the parser threw whole
batches away for** — 45 of 592 text requests in the baseline arm, costing 8 sentences that shipped
untranslated — and that **the gateway's request cache makes a malformed reply permanent**: an
identical retry is answered from cache with the identical broken reply, so no number of retries can
escape it.

## 1. What shipped

| # | change | where |
|---|---|---|
| 1 | **Target-script guard on every translate and repair reply.** A batch with one wrong-script sentence is re-sent with one added line naming the target language; when the retry budget is spent the offending sentences are not cached at all, so the run leaves them untranslated instead of freezing another language into the book. | `internal/translate/langguard.go`, `langcheck.WrongScript` |
| 2 | **`freezeUnrepaired` refuses wrong-language raw text.** Freezing raw text into the proofread namespace makes it proofread *by definition*; a wrong-language translation frozen there would never be retried by any later run — the same shape as the 1 118 sentences a 429 storm once froze (`E` §2.2). | `internal/translate/pipeline.go` |
| 3 | **The reply parser reads a stream of JSON values, not one.** Rescues both malformed shapes this model produces: one object per line, and one object followed by commentary. | `internal/translate/client.go` `mergeNDJSON` |
| 4 | **langcheck is a gate inside `convert`, ahead of lexcheck, the align gate and the judge scope.** Flagged cells are re-translated twice with the foreign-script glossary entries held back and the language named from the first attempt; the residual ships untranslated in v1 and keeps its text with `s: "wrongLang"` in v2. `--langcheck-gate=false` restores the report. | `internal/cli/langgate.go` |
| 5 | **Two glossary entry gates, on built *and* loaded glossaries.** A rendering mostly in a script the target does not write is dropped; a one-word rendering the lexicon does not know while it knows a near spelling is *marked*, not changed, and loses the proofreader's never-change protection. | `internal/translate/langguard.go` `GateGlossary`, `lexcheck.NearMiss` |
| 6 | **gonka defaults follow the probe**, and a `404 model_not_found` prints the served list and stops. | `internal/config/config.go`, `translate.ModelNotFoundError` |

## 2. Method

Two arms of the same book, same model, same settings, separate cache directories; the only
difference is `--langcheck-gate`.

| | |
|---|---|
| source | `panel/epub/pg1661-images.epub.epub` (*The Adventures of Sherlock Holmes*, Gutenberg #1661), `--limit-chapters 2` |
| sentences | 693 (685 unique) × 3 targets = 2 079 cells |
| command | `convert … -t ru,de,fr --provider gonka --model deepseek-ai/DeepSeek-V4-Flash-0731 [--langcheck-gate=false]` |
| defaults in force | batch 8, concurrency 8, 3 retries, `REQUEST_TIMEOUT_SEC` 60, proofread pass on, hybrid alignment (LaBSE, argmax, layer 8) |
| glossary | per target: ru 23 terms, de 108, fr 8 |

*The Wonderful Wizard of Oz* — the plan's first choice, because `19.tbook` is the contaminated book
every De/Fr leak number comes from — **is not on disk anywhere in the workspace**; only the derived
`.tbook` exists. Sherlock is the plan's own stated fallback and is what ran.

Two honest limits on the comparison:

1. **The batch-level guard is unconditional**, as specified, so it is in *both* arms.
   `--langcheck-gate=false` turns off only the post-hoc gate. The arms therefore isolate the gate,
   not the guard; the guard's own contribution is reported separately (it is zero here — it never
   fired).
2. **The gonka gateway answers an identical request body from its cache** (`E` §7.14). Arm B's
   translate phases ran at 736–808 sent/s against arm A's 2.3–10.1, because the prompts were
   identical and the gateway served them from cache. That is *good* for this A/B — both arms carry
   byte-identical text, so every difference below is the gate's — but it means arm B's wall time is
   not a production number.

### The gate's only work on this book was a false positive

```
Language gate: 1 wrong-language cell(s) — re-translating (up to 2 attempts)
Language gate: 0 fixed, 1 still wrong-language; 2 re-translations spent
Language gate [de]: 1 residual of 693 sentences (0.14%)
Language gate: 1 cell(s) ship untranslated (version 1 has no status slot)
Language check: clean (en → ru,de,fr)
```

The cell, verbatim:

> **src** “Is Briony Lodge, Serpentine Avenue, St. John’s Wood.”
> **de** „Ist Briony Lodge, Serpentine Avenue, St. John’s Wood.“

That is a correct German translation. It trips `untranslated` because six of its seven words are
proper nouns that a German text legitimately keeps, which is exactly the shape
`UntranslatedWords = 6` / `UntranslatedMin = 0.85` cannot tell from a copy-through. The gate spent
two re-translations on it, got the same answer both times (the gateway's request cache guarantees
that), and then **deleted a correct translation** because version 1 has no status slot.

**Recommendation, not yet implemented:** scope the version-1 *drop* to the `foreign-script` and
`duplicate-target` signals, which have measured precision on whole-cell leaks (78–88 % of whole
leaked sentences caught, 1.0–4.0 % false-positive rate on clean text — `lexcheck-en-de-en-fr.md`
§6), and let an `untranslated` residual ship with its text and its report line. Keeping a suspected
cell costs a badge; dropping a correct one costs the reader the sentence. All three signals should
still *trigger* a re-translation, which is cheap.

### The guard never fired

Zero batches were re-queued as wrong-script across both arms — 1 290 text requests, 4 158 returned
sentences. There is no verbatim re-queued batch to quote from this run. The guard is nevertheless
not speculative: the served-model probe caught this exact model returning a whole batch in fluent
Chinese twice within a minute, in well-formed JSON that validates
(`gonka-models-2026-09-19.md` § "DeepSeek's two defects"), and that batch is the unit test:

> **src** It is a hobby of mine to have an exact knowledge of London.
> **got** 我的一个爱好是对伦敦了如指掌。

`TestGuardRefusesWrongLanguageBatch` drives that pair through the real pipeline against a mock
server: the Russian batch-mate ships, the Chinese sentence is never cached, the first attempt goes
out without the nudge and the retry with it, and `FillFromCache` hands the assembly
`{"text":"","align":[]}`.

## 4. What the run found that the plan did not ask about

### 4.1 One in ten replies was malformed, and the parser threw the batch away

Baseline arm, `--stats`:

| failure | count | share of 592 text requests |
|---|--:|--:|
| `parse: invalid character 'i' after top-level value` | 30 | 5.1 % |
| `parse: invalid character '#' after top-level value` | 15 | 2.5 % |
| network timeout (60 s) | 42 | 7.1 % |
| `finish_reason=length` (glossary only) | 10 | — |

Both parse classes are the same defect: a complete, correct JSON object with commentary after it.
`parseTexts` rejected it, and the tolerant fallback could not rescue it either — `extractObject`
spans from the first `{` to the last `}`, so it swallows the commentary too. Three rounds of
retries returned the same shape, and **8 Russian sentences shipped untranslated**
(`Validation: 693 sentences, 8 empty`).

The fix reads the reply as a stream of JSON values and keeps what parsed, stopping at the first
thing that is not an object. Re-running the same arm against the same warm cache:

```
[ru] 685 unique sentences — 677 cached, 8 to translate
[ru] translate phase: 8 sentences in 4s
Validation: 693 sentences, 0 empty, 0 offset_errors, 0 struct_errors — OK
Total wall time: 23s
```

**All 8 recovered, in 24 seconds and 3 requests.** Arm B, produced with the fix, recorded zero
failures of either class.

### 4.2 The gateway's request cache makes a malformed reply permanent

Arm B hit a different class — 90 replies that stop mid-JSON (`unexpected end of JSON input`) with
no `finish_reason=length`. Those are genuinely incomplete and the parser is right to reject them.
What matters is that **they never recovered**: a warm re-run re-sent the same 16 French sentences,
got the same truncated reply on every one of three rounds, and they still ship untranslated. The
gonka gateway answers an identical request body from cache, so a retry that changes nothing cannot
escape a broken answer.

The guard already exploits the converse — its nudge changes the body, which is why a wrong-script
retry can succeed at all. **Follow-up:** vary the request body (the OpenAI `user` field already
exists as `Options.UserTag`, used by the benchmarks for exactly this) on a retry after a parse
failure. Cheap, and it is the difference between losing 16 sentences and not.

### 4.3 The glossary sample pass does not fit this model

`buildSampleGlossary` asks for up to 120 entries in one reply — the largest single output the
pipeline ever requests. On this model it returns `finish_reason=length` for ru and fr (de fit), and
the gateway then serves the same truncated reply in ~90 ms on every retry: 51 s for the first
attempt, four cached failures after it. A failed sample pass used to abort the whole run, which
would have made the new gonka default **unable to convert any book at all**. It is now non-fatal:
the run says so and continues with the mined terms, and only a failure of *both* passes is an
error. Cost on this book: ru 23 terms instead of ~100, fr 8 instead of ~90; de unaffected at 108.

This is worth a proper fix (batch the sample pass, or lower `glossarySampleCap` on gonka) before
any glossary experiment runs on this model — the fr glossary in this run is not representative.

### 4.4 The glossary script gate is exercised, the lexicon gate is not

On en→de and en→fr the entry gates dropped 30 and 16 entries respectively, every one of them
`rendering equals the source term` — an English name a German or French text legitimately keeps.
That rule is pre-existing; what is new is that it now says so, once per reason with an example
rather than once per entry:

```
Glossary [de]: dropped 30 entries — rendering equals the source term, e.g. "Holmes" → "Holmes"
```

The new script rule (`rendering is in a script <target> does not write`) fired zero times here,
because no glossary in this run was built for the wrong language — which is the point: it is the
guard against a sidecar that was. The suspect gate found nothing either; all three sidecars carry
an empty `suspect` list. Both are covered by unit tests against the measured cases
(`Irene Adler → Айрин Адлер` for de, `escritoire → эскртуар` for ru).

## 7. What is left undone

- **The version-1 drop is too wide** (§3): it should not delete a cell on the `untranslated` signal
  alone. One-line change, but it wants its own before/after.
- **A retry after a parse failure should vary the request body** (§4.2), or the gateway's cache
  guarantees the same broken reply.
- **The glossary sample pass needs batching on gonka** (§4.3); until then the fr and ru glossaries
  on this model are short.
- **`parseChunks` (the align reply) did not get the stream parser** — same exposure, deliberately
  left alone to keep this change inside the translate path.
- **Oz was not run** (§2): its EPUB is not on disk. `19.tbook`'s producer settings are not
  reproducible without it, so the 73 %/56 % Cyrillic figures stay a historical number rather than a
  before-arm.
- **The guard has no live positive** (§3): it never fired. A real demonstration needs either the
  gateway to repeat its Chinese batch or a deliberately contaminated glossary arm.

## 8. B1b — the three follow-ups, same day

§7 listed three things B1 left undone. All three are in; `go build ./... && go vet ./... &&
go test ./...` is green at 25 packages.

### 8.1 The gate no longer deletes a correct translation

`langcheck.Gating(kind)` is now the single place that decides whether a flag may act on a cell,
and it answers yes for `foreign-script` and `duplicate-target` only. The reasoning is in the
function's own comment, with the verbatim case that forced it:

```
src  “Is Briony Lodge, Serpentine Avenue, St. John’s Wood.”
de   „Ist Briony Lodge, Serpentine Avenue, St. John’s Wood.“
```

All three kinds still *trigger* a re-translation — that is cheap and may fix a real copy-through —
but an `untranslated`-only residual is reported and nothing more: version 1 keeps the translation,
and version 2 badges it `s: "unverified"` with its `v: {by: langcheck, why: untranslated}`, never
`wrongLang` and never a `lang` (which §11.1 would reject without `wrongLang` anyway).

Re-run over the same warm cache that produced arm A, gate on:

```
Language gate: 1 flagged cell(s) — re-translating (up to 2 attempts)
Language gate: 0 fixed, 1 still flagged; 2 re-translations spent
Language gate [de]: 1 residual of 693 sentences (0.14%)
Language gate: 1 of those are untranslated only — reported, not acted on
Language gate: 0 cell(s) ship untranslated (version 1 has no status slot)
Language check [de]: 1 flagged (1 untranslated)
Validation: 693 sentences, 0 empty, 0 offset_errors, 0 struct_errors — OK
```

`0 empty`, against `18 empty` in the B1 arm-B file: the German address survives and the flag still
reaches the report. The same cache written as `--format v2`:

```
Statuses: 1 unverified
Validation: valid version-2 archive (0 warnings)
```

### 8.2 The align reply gets the same stream parser

`parseChunks` and `parseTexts` now share one generic `mergeJSONStream[T]`. The align pass reads the
same model over the same gateway and fails the same two ways — an object followed by commentary,
or one object per line — and used to throw the whole align batch away for it. A truncated reply
still fails, as it must: nothing complete arrived.

### 8.3 A parse-failure retry varies the request body

The gateway answers an identical body from cache, which is why 16 French sentences came back
truncated on six consecutive attempts in §4.2 and shipped untranslated. After a parse failure the
client now rewrites the request with the OpenAI-standard `user` field set to `retry-<attempt>`
(keeping whatever the caller had there, which is how the benchmarks already bust this cache). The
prompt, the sentences and the sampling are untouched; the first attempt still sends no tag, so
production request bodies are unchanged on the happy path.

This is the same mechanism the target-script guard already used — its nudge line changes the body —
now applied to every parse failure on both the text and align paths.

## 9. B1c — the glossary sample pass, diagnosed and fixed

§8.5 left one thing that would have confounded every De/Fr arm: on
`deepseek-ai/DeepSeek-V4-Flash-0731` the glossary's sample pass returned **nothing** for Russian
and French, so those books ran on mined names alone (fr: 8 enforced terms).

### 9.1 The cause is the entry cap, not any of the suspects

Truncated replies used to be unquotable — the client discarded the content before returning
`errTruncated`, which is why B1 could only say "it cannot be quoted". The partial now rides along
with the error to `Options.OnContent`, and one capture settles it. En→fr, Sherlock ch.1–2, the
production prompt at its production size:

```
200 sentences, cap 120 → finish_reason=length, 8 879 bytes, 250 entries opened
```

The reply's tail:

> …{"src":"police","tgt":"police"},{"src":"official","tgt":"officiel"},
> {"src":"European","tgt":"européen"},{"src":"history","tgt":"histoire"},
> {"src":"kingdom","tgt":"royaume"},{"src":"province","tgt":"province"},
> {"src":"monarch","tgt":"monarque"},{"src

**The model ran to 250+ entries against a prompt that said "At most 120", and by then it had left
key recurring terms behind and was enumerating ordinary vocabulary** — *police*, *kingdom*,
*monarch*. It was cut mid-word at roughly 3 000 output tokens, nowhere near the 16 384 the gateway
advertises.

So none of the suspects is the cause: not the 16 384 cap (it stopped at a fifth of it), not the
120 s router deadline (51 s), not `max_tokens` (the client sends none), not JSON mode (the reply is
well-formed until it stops). **The cap is the only number this model obeys, and only while it is
small.** Measured, one call each:

| sentences | cap | result |
|--:|--:|---|
| 200 | 120 | **cut**, 250+ entries, 8 879 B, 51 s |
| 100 | 40 | 48 entries (overshot the cap, completed), 18 s |
| 100 | 30 | **30** entries, 1 085 B, 4 s |
| 50 | 40 | 20 entries (ran out of terms first), 842 B, 2 s |
| 50 | 30 | **30** entries, 1 458 B, 3 s |
| 50 (ru) | 30 | **30** entries, 48 s |
| 50 (de) | 30 | **30** entries, 9 s |

At 30 the cap is honoured exactly, in all three languages.

### 9.2 The fix

`buildSampleGlossary` now splits the same 200-sentence sample over **4 concurrent calls of 50
sentences at 30 entries each**, merged and de-duplicated by lowercased head term in call order, and
capped at the same `glossarySampleCap = 120` overall. The chunks are *interleaved* (chunk k takes
every 4th sentence from k), so each call still sees the whole book rather than one chapter.

Failure handling is explicit: a chunk that fails costs only itself, and the pass returns an error
only when every chunk failed (B1's non-fatal fallback to mined terms then still applies). A
truncated reply never reaches the parser — the client turns `finish_reason=length` into an error
before parsing — so a cut-off list is a retried failure and can never be accepted as a partial
glossary, which is the outcome that would quietly enforce half a term list on a whole book.

`GlossPromptVersion` is bumped **g1 → g2**: the cap number is interpolated into the prompt text, so
the contract changed even though its semantics did not. Cached glossaries rebuild, which is correct
— every one built on this model is currently mined-only.

### 9.3 Verification: `--provider gonka --only-glossary`, default model

Enforced term counts per language, before and after, same book and same command:

| ch.1–2, sampled terms before | **0** | 84 | **0** |
| **ch.1–2, after** | **119** | 100 | **91** |

French goes from 8 enforced terms to 91 on the same two chapters. Russian from 23 to 119. German,
